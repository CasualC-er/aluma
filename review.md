# Review — Alúma compiler

## Summary

Pass 1 (2026-11-11). Scope: the whole repo. `src/`, `lib/`, `tests/`,
`documentation/adr/`, `Cargo.toml` and CI config do not exist yet, and
`documentation/ir.md` and `documentation/amendments.md` have not been created, so
there is no implementation to review. This pass is therefore a spec-compliance
review of the two Phase 0 planning artifacts that do exist — `TODO.md` and
`documentation/implementation_plan.md` — against `documentation/language_reference.md`.

What is done well: the plan is unusually honest about the hard parts, and several
decisions are derived from the spec rather than from habit — D4 correctly rules out
conservative GC from the exact-recount requirement of [8.5.1], D5 correctly refuses
to coalesce step charges because the yield point is observable through [8.4] and
[8.3], D6 ties explicit unwinding to the "1 step per unwound frame" charge, and D7
derives 10^18 limbs from the `⌈p/18⌉` size row of [8.4] instead of picking a
convenient radix. D8's byte-exactness discipline is the right fixpoint boundary, and
putting the conformance harness and the doc-example corpus first (D13.4) is the
correct response to having no interpreter. The phase graph's observation that `almc`
is single-task, so self-hosting does not wait on Phase 6, is a genuinely useful
scheduling result.

Findings below concern the conformance harness design (which everything else depends
on, and which cannot yet express the shapes the spec's own examples take), one
determinism hole in the `-O0`/`-O2` differential, a gap between the runtime report
format of [7.5] and the site-table design, missing compile-option plumbing for
`almc0`, and some lexical details where the build list does not match [2]/[10].

Verdict: no blocking defects in code (there is none). Address the harness findings
(the four `major` items touching Phase 0 and Phase 3b) before populating
`tests/docs/`, since the test format is hard to change once a few hundred extracted
cases depend on it.

Counts: 0 critical, 5 major, 5 minor.

Pass 2 (2026-11-11). Scope: Phase 0 groundwork (`alm-core`, `almtest`, workspace files). Verified against the spec: every default in the `[8.9]` table matches `Options::default()` value for value (including 16 Mi, 64 Mi, 256 Mi); the 22 predefined exceptions of `[7.5]` are all present and correctly spelled; the step costs of `[8.4]` (including all 13 one-step task operations), the size-unit table, `⌈p/18⌉`, the add/multiply limb rules and the copy-price rule (total units rounded up once, plus one per object) match the text, and the two worked sizes (4 and 1001) are asserted. Praise: the manifest design (a test is a directory, `--path` pointing at it, `#!error` line annotations that are legal comments, exact-set matching of error lines) is a real answer to pass-1 findings 1 and 2; the A-002 treatment of `--seed` and the host-path-free `identity()` are the right calls; saturating arithmetic in the size functions is correct for `OutOfMemory` accounting. Remaining pass-2 concerns: a parser bug that rejects ordinary expected output such as `[1, 2, 3]`, no way to give a test standard input or `args()`, several doc references to files that do not exist yet, and test gaps. Coder has not marked any pass-1 finding resolved, so none is verified as fixed; findings 1 and 2 are substantially answered by the design but stay open until the stdin/args gap below is closed and the format is exercised. Pass-2 counts: 0 critical, 2 major, 8 minor.

Pass 3 (2026-11-11). Scope: ADR-001..014, `ir.md`, `amendments.md`, the rewritten `manifest.rs`, the new tests in `alm-core`, the TODO ticks and CI. Of the 19 `resolved` findings, 17 are fixed (some with caveats noted in new lines), 1 is not fixed (`exception.rs:36`: the `index()` test does not catch an omitted variant appended at the end) and 1 is only partly fixed (`manifest.rs:273`: stdin and `args` exist, but outside-event pinning and stdin shape are not covered). The `wontfix` at `lib.rs:63` is accepted in substance: TODO.md:57 does plan multi-error recovery. The remaining objection is that "good enough recovery" is weaker than the harness's "exactly the annotated set", so cascaded secondary errors will fail tests; consider a per-test opt-out. Praise: ADR-007 now states the representation and the 3-versus-2 case explicitly; A-001/A-002 are sound and match `alm-core::options`; the ADRs consistently say which spec rule forces a choice; the 52-keyword, golden-identity and copy-price tests are exactly what was asked. Main new concerns: `ir.md` section 6 does not say when the call chain is captured given status-and-branch unwinding, and ADR-007 does not say whether limb counts are static or value-dependent. Pass-3 new findings: 0 critical, 2 major, 16 minor.

Pass 4 (2026-11-11). Scope: Phase 1 lexer (`token.rs`, `lex.rs`, `lex_corpus.rs`) against [2] and the lexical productions of [10]. Verified correct: the 52-keyword table is read out of the spec, identifiers are ASCII and case-sensitive, the `#`-inside-a-literal rule holds (literals are read before comments are considered), both spellings of the over-max integer are handled and `IntValue::MinIntMagnitude` is a sound design (2^63 is the only value that needs deferred checking; `Fixed` is unbounded by design and nothing else in the stream needs the treatment), the escape set is exactly the spec's eight with every other escape rejected, `\u{h}` enforces one to six digits and a valid code point, fixed-literal scale and A-001 are right, all byte-versus-char slicing I could construct is on boundaries (no panic found), and the one-mistake-one-diagnostic handling in char literals is good. Main problems: a backslash before a line break is swallowed as an "escape", which lets a literal run over the line break the spec forbids and swallows following source lines (cascade of three diagnostics, wrong tokens); a long run of invalid characters overflows the stack (reproduced: 200,000 `@` aborts the process); a run of invalid characters or a non-ASCII word gives one diagnostic per character and can leak a keyword (`senal` with a tilde-n lexes `and`-style fragments); a raw carriage return is accepted inside a literal; and several silently-accepted shapes (`a_b`, `1_000`, `12abc`) are left to the parser. Tests: no test pins the backslash-newline case, a raw `\r`, spans of literal tokens, or the boundary `\u{10FFFF}`/`\u{110000}`; one token.rs test is vacuous. Pass-4 counts: 0 critical, 2 major, 9 minor.
